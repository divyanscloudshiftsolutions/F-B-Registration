## Issue 9: Express Gateway Rate Limiter Lockout (`429 Too Many Requests`) & Aggressive Polling Flood

| Attribute | Details |
| :--- | :--- |
| **Project Overview** | API Gateway rate limiter configuration, development environment bypass, and frontend background sync loop optimization. |
| **Problems Identified** | 1. Development testing and multi-tab usage triggered HTTP 429: *"Too many requests from this IP. Please try again after 15 minutes."*<br>2. Root Cause 1: `DataContext.tsx` ran an aggressive background sync loop every 3 seconds (`setInterval` fetching `/api/tokens/active`, `/api/tables`, and `/api/reservations`), generating 60 requests/minute (900 requests/15 mins) per tab.<br>3. Root Cause 2: In `backend/src/server.ts`, the Express rate limiter had a global hard limit of 1,000 requests per 15 minutes with no bypass for `localhost` (`127.0.0.1`, `::1`) or non-production environments (`process.env.NODE_ENV !== 'production'`). |
| **Resolution** | 1. Added a `skip` callback to express rate limiter in `server.ts` that bypasses rate limiting in development (`process.env.NODE_ENV !== 'production'`) and for local loopback IPs (`127.0.0.1`, `::1`, `::ffff:127.0.0.1`).<br>2. Raised development rate limit ceiling to 50,000 requests while preserving the strict 1,000-request DDoS defense for production.<br>3. Optimized `DataContext.tsx` background sync interval from 3,000ms (3s) to 15,000ms (15s).<br>4. Added a document visibility check (`if (typeof document !== 'undefined' && document.hidden) return;`) in `DataContext.tsx` to completely pause polling when the tab is hidden or minimized. |
| **Activities Completed** | 1. Verified backend TypeScript compilation (`npx tsc --noEmit`).<br>2. Verified frontend production build (`npm run build`).<br>3. Confirmed active 429 lockout cleared immediately and API endpoints return HTTP 200/304.<br>4. Monitored server access logs to confirm background request volume decreased significantly. |
| **Files / Modules Updated** | - `backend/src/server.ts`<br>- `web-frontend/src/context/DataContext.tsx` |
